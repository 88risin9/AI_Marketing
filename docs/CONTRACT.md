# Implementation contract
Python Flask SQLite. Root owns app/server.py, app/db.py, app/quotes.py, app/pdf_export.py, run.py, integration tests, README. frontend agent owns templates/index.html static/app.js static/style.css only. domain agent owns app/ai.py app/matching.py and domain tests. import agent owns app/products.py templates downloads in assets/ and tests for products.
JSON APIs: success returns object itself; error {error: Chinese text}, status 400/409/503. All requests use ?workspace=live|demo (default live). POST/PUT/DELETE requests must include X-Local-Request: 1. No CSRF tokens otherwise. Server only 127.0.0.1, Host/origin restricted. data/live.sqlite3 and data/demo.sqlite3.
GET /api/state -> {workspace, products:[],customers:[],inquiries:[],quotes:[],activities:[],ai:{configured,provider,model,base_url,timeout},company:{name,email,address},today}. All entity fields are JSON strings/numbers/arrays; id integer, created_at/updated_at ISO strings. no API key returned.
Product {id,supplier,name,name_en,model,category,specs:{poles,current_a,voltage_v,curve,breaking_ka,...},unit,purchase_price,currency,moq,lead_time,source,updated_at,missing:[]}. Decimal values represented as strings. category default MCB. preserve model/unit verbatim.
POST /api/products or PUT /api/products/:id body Product; server returns product. Product module validate_product(payload) -> normalized product dict with missing[], raises ValueError for invalid values, permits missing values. parse_import(filename,bytes) -> {rows:[{row:2,product:{...},errors:[],warnings:[]}],errors:[]} ; template_bytes(format, demo=False) -> bytes. POST /api/import/preview multipart file -> above; POST /api/import/commit {rows:[Product,...]} atomic validates all. GET /api/templates/products.csv or products.xlsx; GET /api/templates/example.csv or example.xlsx -> downloads.
Customer {id,name,country,contact,source,notes}. POST /api/customers or PUT /api/customers/:id.
Inquiry {id,customer_id,title,original_text,status,next_followup,reason,analysis:null|Analysis,analysis_reviewed:false,selected_product_ids:[],selection_note,reply_draft,followups:[],baseline_minutes,actual_minutes,created_at,updated_at}. POST /api/inquiries creates, PUT /api/inquiries/:id edits whitelisted values; original_text edits invalidate analysis/selection. status Chinese enum 待补充,待报价,已报价,跟进中,成交,关闭. Editing analysis/selected products is recorded as human edit activity. POST /api/inquiries/:id/analyze {mode:'live'|'demo'}: analyze(original_text,mode) -> Analysis; server measures duration, records success/failure, persists on success only; demo only allowed demo workspace. POST /api/inquiries/:id/review {analysis:Analysis,reply_draft,selected_product_ids,selection_note,baseline_minutes,actual_minutes} persists reviewed analysis and selection; server validates matching, hard conflicts cannot select; pending items require explicit selection_note. POST /api/inquiries/:id/followups {note,next_followup,status,reason} saves.
Analysis {requirements:[{field,value,evidence,kind:'stated'|'inferred'|'missing'}],questions:[strings],reply_draft:string,warnings:[strings],mode:'live'|'demo'|'manual'}. Canonical fields product,quantity,unit,poles,current_a,voltage_v,curve,breaking_ka,delivery,other. requirements can add extra fields. evidence exact substring of original text for stated. Missing value ''. Inferred never used to successful matching. supports first version one requirement group; multiple groups explicitly warning/require splitting rather than merging. Manual UI should let edit kind/value/evidence and add fields.
app.ai get_config() -> public safe config incl configured; analyze(text,mode='live') -> Analysis or raises ValueError/RuntimeError with Chinese safe error. credentials env/file .env loaded server side; AI_PROVIDER openai|compatible; AI_BASE_URL,AI_MODEL,AI_API_KEY,AI_TIMEOUT. OpenAI Responses with structured output, compatible chat/completions path. urllib stdlib. no request logs. Only text for current inquiry sent (no product costs/customer contact separate). Schema strict, postvalidate evidence. Explicit demo uses deterministic example extraction never fake real success.
GET /api/inquiries/:id/matches -> {candidates:[],message}. app.matching match_products(analysis,products) -> {candidates:[{product_id,status:'eligible'|'pending'|'conflict',reasons:[],conflicts:[],pending:[]}],message}. eligible means evidence supports all key parameters, still human approval. Unknown unit etc pending. hard conflicts never eligible; no substitutions by model. Numeric equivalent normalize safe units; incompatible/ranges unclear pending. matching deterministic.
Quote {id,inquiry_id,number,version,status:'draft'|'approved',sent_at,created_at,snapshot:{company:{name,email,address},customer:{name,country,contact},currency,lead_time,valid_until,payment_terms,trade_terms,customer_note,internal_note,lines:[{product_id,description,model,specs,quantity,unit,unit_price,line_total,purchase_price,cost_currency,fx_rate,cost_total}],other_costs,total,estimated_profit,margin_pct,cost_warnings:[]},validation_errors:[]}. GET state quotes includes snapshot and validation_errors. POST /api/quotes {inquiry_id,base_quote_id(optional),currency,lead_time,valid_until,payment_terms,trade_terms,customer_note,internal_note,other_costs,lines:[{product_id,description,quantity,unit,unit_price,fx_rate}]} always creates NEW immutable version, no mutation. fx_rate means 1 cost_currency = X quote_currency, needed if differs, else 1. price nonnegative decimal; qty >0; totals Decimal line rounded 2 (JPY 0, currencies supported USD/EUR/CNY/GBP/JPY/AUD/CAD); internal other_costs in quote currency. Quote uses products snapshots, values saved unaffected by product updates. For draft missing permitted, approve blocked if missing or no reviewed selection. POST /api/quotes/:id/approve validates, marks approved; POST /api/quotes/:id/sent {sent:true|false} manually records. GET /api/quotes/:id/preview -> standalone English HTML customer whitelist only. GET /api/quotes/:id/pdf -> PDF draft watermarked, approved official. Ensure customer artifact omits cost/supplier/internal. Demo artifacts say FICTIONAL SAMPLE. POST /api/company {name,email,address}. GET /api/backup downloads JSON versioned snapshot of CURRENT workspace no secrets. POST /api/restore multipart file only validates schema, creates pre-restore backup automatically, atomic replaces CURRENT workspace; requires JSON workspace equals current workspace.
GET /api/health {ok:true}. Dashboard can derive counters/status/activity efficiency; no savings without baseline AND actual_minutes, demo AI never included in real efficiency. Activity {id,inquiry_id,kind:'ai_success'|'ai_failure'|'human_edit'|...,duration_ms,mode,message,created_at}; safe error text only.
